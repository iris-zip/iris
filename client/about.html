About Iriszip

Iriszip started from a simple frustration: to send someone a file, you usually have to upload it to a company first — and trust that company with whatever's inside.

Many file-transfer services rely on cloud storage, accounts, advertising or analytics. Iriszip is built the opposite way. It doesn't hold anything. It encrypts your file on your device, connects you to the person you're sending to, and gets out of the way.

It's an independent project — not a startup chasing your data, just a tool that does one thing and respects you while doing it. Built and maintained in Georgia.

Which devices

Any phone, tablet, laptop or desktop with a browser from the last few years — whatever the ecosystem. Nothing to install on either side. TV and console browsers are a mixed picture: on the newer ones the chat and the transfer itself work, but saving a received file depends on whether that browser can download at all, and several older sets can't run Iriszip. If you try one, we'd like to hear how it went.

Tor Browser works at its Standard security level. The higher levels turn off WebAssembly, which the encryption core needs, so Iriszip deliberately refuses to start rather than run unverified. On Tor, transfers use the relay lane, because Tor disables WebRTC by design.

If Iriszip is useful to you, the best way to keep it running is to support it.

License

Iriszip is open source. The client — the code that runs in your browser — is MIT licensed: read it, reuse it, build on it. The encryption core is Apache 2.0, so anyone can reuse the audited cryptography, even in a commercial product. The server is licensed under the GNU Affero General Public License v3: free to read, modify, self-host, and run — including inside a company — on the condition that if you offer a modified version to others as a service, you publish your changes too. Companies that need to embed Iriszip in a proprietary product without publishing their changes can buy a commercial license instead.
